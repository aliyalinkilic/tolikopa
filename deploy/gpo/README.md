# GPO Deployment Files

The files in this folder are for rolling the agent out to a Windows domain. Step-by-step guide:
[`../../docs/GPO-DEPLOYMENT.md`](../../docs/GPO-DEPLOYMENT.md) (a summary is also on the panel's **Setup** page).

| File | Purpose |
|------|---------|
| `bootstrap.ps1` | Placed in NETLOGON; the GPP Scheduled Task runs it as SYSTEM — it idempotently installs/updates/repairs the service. |
| `config.example.json` | Template for `config.json`. Fill in `ingest_token` (from the server's `.env`) and `tls_ca_pem` (the panel's certificate, `deploy/tls/tolikopa.crt`). |
| `ScheduledTasks.xml` | Reference definition of the GPP Scheduled Task (advanced/import). Recommended: create it through the GPMC UI. |

> The recommended path is not to move these files by hand, but to run the `tolikopa-setup.exe`
> tool generated by the panel (see the guide). This folder is the source of the `bootstrap.ps1`
> the tool uses.

## Quick summary (if you want to prepare it by hand)

1. Get the (built) `tolikopa-agent.exe` from the server: the panel's Setup page or `agent/dist/tolikopa-agent.exe` (the file name is the same as in NETLOGON, no renaming needed).
2. Download a ready-made `config.json` from the panel's Setup page (`ingest_token` and `tls_ca_pem`
   come pre-filled). If you prepare it by hand, copy `config.example.json` and fill it in (values
   from `deploy/.env` and `deploy/tls/tolikopa.crt` on the server).
3. On the DC: put `tolikopa-agent.exe`, `bootstrap.ps1` and `config.json` under `\\CORP\NETLOGON\Tolikopa\`.
4. In GPMC, create a GPO, add a GPP Scheduled Task (with the settings from the guide) and link it to the target OU.
   On the manual path you also have to set up the panel's DNS record and the certificate trust yourself
   (`tolikopa-setup.exe` does these automatically).
5. On a test PC run `gpupdate /force`; it shows up in the panel within a few minutes.

To read the values on the server by hand (from the repository root):
```bash
sudo grep INGEST_TOKEN deploy/.env
cat deploy/tls/tolikopa.crt      # tls_ca_pem — line breaks are written as \n in the JSON
```
